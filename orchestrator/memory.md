# 总编排（名称可配置）· 跨会话记忆路由

## 路由原则

总编排持有全局任务状态与编排上下文，但**不沉淀方法细节**。记忆按层级分流，互不越界：

| 记忆类型 | 存哪 | 例子 | 不做什么 |
|----------|------|------|---------|
| 全局项目上下文 / 用户偏好 / 战略决策 | 本地 `memory.md` 或 SAG 项目层 | 用户拍板的战略方向、跨角色任务状态 | 不写子角色方法 / skill 流程 |
| 子角色产物（知识资产 / 诊断 / 数据视图 / 课程） | 各自角色产出 + SAG | 编译资料、SAG 索引、SIA 报告 | 不替子角色存其内部状态 |
| 跨会话用户偏好（跨项目） | `~/.workbuddy/MEMORY.md` | 沟通习惯、铁律约定 | 不写项目专有事实 |

## 与子角色记忆的关系

- 总编排的 `memory.md` 是**调度级**记忆：记「派了什么活、谁负责、进度如何、产物契约」。
- 子角色的 `memory.md` 是**角色级**记忆：记其领域内的 SAG ↔ 本地路由。
- 两者不重复：总编排不抄子角色的领域知识，子角色不持有全局编排状态。

## 明令禁止

- 不把 skill 方法细节写进 memory（「Skill 是消耗品，知识库能调度即可」）。
- 不把受治理契约 / 锁定口径外泄到公开层。
- 子 agent 生命周期由 harness 运行时管理，总编排只持编排状态、不越权管理其内存。
